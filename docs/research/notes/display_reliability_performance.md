# Display, reliability and performance complaints about dual-subtitle tools

Scope: Language Reactor (LR), Trancy, Immersive Translate, Dualsub, Netflix Multi-Subtitles 2.0, Hulu Dual Subtitles, other Netflix/Hulu/Disney+ dual-subtitle extensions. Research date: 2026-10-05. Most evidence comes from the Language Reactor community forum (Discourse) and Chrome Web Store (CWS) review pages, read through a fetch tool that summarizes pages. Quotes below are the text the tool returned as verbatim. Spot-check them before publishing. Search engines returned no Reddit threads for these queries, so Reddit is not represented (see Gaps).

## Display / UI problems

### Takeaway
The most consistent display complaints are about subtitle **position**: on-video dual subtitles sit too high, especially with larger fonts; their position cannot be pinned or saved, so users drag them down every episode; and there is no way to adjust position at all in some tools. Other complaints are **double subtitles** (the site's native captions plus the extension's), **fullscreen losing the subtitles**, the **video shrinking** when subtitle panels are on, and **right-to-left text rendering**. Each display issue has only a few reports (1–5 posts), far fewer than the reliability complaints.

### Cited Findings
- **Subtitles too high with bigger fonts / position not remembered (LR, Netflix):** "When using bigger font the double subtitles from Language Reactor are by default almost in the middle of the screen." and "I want them as low on the screen as possible, which is further hindered by Netflix UI popping up." — Bartek_Z, 2024-12-04, 1 like. The user asks for a button to pin subtitles to the bottom or top because they must reposition them by hand for every new video. — [LR forum: Pin on-video subtitles on the bottom of the screen](https://forum.languagelearningwithnetflix.com/t/pin-on-video-subtitles-on-the-bottom-of-the-screen/25297)
- **No position control (LR, CWS low-star review):** "add a feature for users to adjust the position of the subtitles/translation" — Ian, 2026-08-20 — [CWS Language Reactor reviews](https://chromewebstore.google.com/detail/language-reactor/hoombieeljmmljlkjmnheibnpciblicm/reviews)
- Other LR forum threads ask for the same position control: [Change position of the subtitles](https://forum.languagelearningwithnetflix.com/t/change-position-of-the-subtitles/13531), [How to move the subtitles to below the screen](https://forum.languagelearningwithnetflix.com/t/how-to-move-the-subtitles-to-below-the-screen/25246), [Please put the subtitles on the videos](https://forum.languagelearningwithnetflix.com/t/please-put-the-subtitles-on-the-videos/5425). These titles show users want both directions: some want subtitles moved off the picture, others want them moved back onto it. Search snippets said users want to drag subtitles "similar to how YouTube handles it". That wording was not verified verbatim.
- **Double subtitles (native captions plus the extension's):** "When I do that I get two sets of subtitles when I only want the bottom one below the picture." — DuaneDH, 2021-09-08 (older report) — [LR forum: Post your rants about Language Reactor update](https://forum.languagelearningwithnetflix.com/t/post-your-rants-about-language-reactor-update-here/5050/20). A related request asks LR to block subtitles burned into the video: [Please add a blocker for baked-in/burnedin/hardcoded subtitles](https://forum.languagelearningwithnetflix.com/t/please-add-a-blocker-for-baked-in-burnedin-hardcoded-subtitles/38931). Turning subtitles off is also confusing: [Turn Off Dual Subtitles](https://forum.languagelearningwithnetflix.com/t/turn-off-dual-subtitles/11116).
- **Fullscreen hides subtitles (LR on YouTube/custom media, Edge/Chrome):** "My subtitles have moved from being on the video, to under the video. When I click fullscreen the subtitles are not shown." — brendon, 2025-03-01. A second user replied "UP. Still relevant. I have the same problem too." — theex, 2025-03-04. No fix was posted in the thread. — [LR forum: Subtitles not showing when in fullscreen](https://forum.languagelearningwithnetflix.com/t/subtitles-not-showing-when-in-fullscreen/28112)
  - Technical cause, documented generally: when the browser puts only the `<video>` element into fullscreen (for example from the context menu), an overlay outside that element is not visible — [Mozilla bug 1578168](https://bugzil.la/1578168)
- **Subtitle panels shrink the video:** "the video window becomes quite small—occupying only about a quarter of the screen" when the bottom and sidebar subtitle panels are both on — Fisher_County, 2025-07-07 — [LR forum: Allow Larger Video Area When Using Both Bottom and Sidebar Subtitles](https://forum.languagelearningwithnetflix.com/t/allow-larger-video-area-when-using-both-bottom-and-sidebar-subtitles/31896)
- **Right-to-left scripts rendered in the wrong direction (Trancy):** "Arabic should be from right to left but your extensions renders it left to right" — Glenn, 2026-09-30; "Arabic is written from Right to left, not left to right." — Ahamed Nuzhan, 2026-07-31 — [CWS Trancy reviews](https://chromewebstore.google.com/detail/trancy-ai-subtitles-immersive-tr/mjdbhokoopacimoekfgkcoogikbfgngb/reviews)
- **Subtitles disappear too fast (LR):** "subtitles will go away too quickly before the person has even finished" — Frank Steinman, 2026-09-24. The reviewer later said it was fixed. — [CWS Language Reactor reviews](https://chromewebstore.google.com/detail/language-reactor/hoombieeljmmljlkjmnheibnpciblicm/reviews)
- **Badly broken lines / sentence segmentation:** "the sentences cut off at weird places that makes the sentences incomplete and mixing up together." and "I can't save the sentences because it's incomplete so it is not usable to study." — Ash, 2022-11-03 (older report). Other users blamed the source subtitle files. — [LR forum: Subtitles cutting off in the wrong place](https://forum.languagelearningwithnetflix.com/t/subtitles-cutting-off-in-the-wrong-place/9257)
- **Users can't find styling options (Hulu):** "How to customize subtitles?" — Xu Yingze, 2026-03-05 — [CWS Hulu Dual Subtitles reviews](https://chromewebstore.google.com/detail/llbekaiifiopdmojkacmkaihdenoffnh/reviews) (5 ratings, 4.0★, 724 users). Another review on the same page praises being able to turn off the English line and keep only the foreign one: "i was even able to turn off the english subtitles and keep the foreign language I wanted to watch" — Caleb Morris, 2024-12-11.

### Inferences
- A useful product should have a fixed default position near the bottom that stays below the site's control bar. The position should be saved across episodes and sessions, with simple "pin bottom / pin top" options rather than only dragging.
- The extension should hide the site's native captions automatically while dual subtitles are on, so users don't see two sets of subtitles.
- The overlay has to stay visible in every fullscreen path. One approach is to attach it inside the player's fullscreen container.
- Right-to-left scripts (Arabic, Hebrew, Persian) need `dir="rtl"` or `dir="auto"` per line. This is cheap to add, and Trancy is still criticized for missing it in 2026.
- Font size and position interact: a larger font makes the two-line block grow upward and cover the middle of the picture.

### Gaps
- No user reports found about picture-in-picture, letterboxed video, mobile/tablet layouts, or dark/light themes. These may be uncommon complaints, or simply outside what the searches reached.
- Not enough evidence to say how many users care which language is on top.
- Reddit threads (r/languagelearning, r/LearnJapanese, r/Hulu) did not show up in search, so the size of these display complaints on Reddit is unknown.

## Reliability problems

### Takeaway
Reliability is by far the biggest category. The dominant failure is subtitles never loading after the streaming site changes its player or data format. For Language Reactor on Netflix, users reported "stuck on Loading subtitles…" again and again from mid-2025 through mid-2026, across many forum threads (one has 84 replies and 4,365 views), and some called the product abandoned. Other reliability issues are subtitles failing on the **next episode**, the source language not being detected, server-side ASR errors, **daily re-login**, and tools working on one platform (YouTube) but not another (Netflix, Disney+, Coursera).

### Inferences
- Breakage after a player update is the most important reliability risk. In this evidence, the length of an outage (weeks), together with no response from the vendor, does more damage to trust than the failure itself. A visible status/version message ("Hulu changed its player, fix shipping") and fast patch releases set a tool apart from competitors.
- The extension should keep working across in-page navigation: next-episode autoplay, title changes and seeking. "Stops working on next episode" and "refresh to fix" are common complaints.
- Users prefer subtitles that load without an account and without server-side ASR. Login expiry and server errors produce angry 1-star reviews.

### Gaps
- No reports found specifically about ads (subtitles shown over ad breaks or failing after them) on Hulu or other ad-supported tiers. This is a gap in the evidence, not proof the problem doesn't occur.
- No user reports found on seeking breaking subtitles, multiple tabs, conflicts with other extensions (beyond the generic advice to disable other extensions), or region restrictions.
- No Hulu-specific complaint threads found. The one Hulu dual-subtitle extension found has only 5 ratings.
- Reddit was not reached.

## Performance problems

### Takeaway
Performance complaints show up far less than reliability complaints. The ones found concern slow subtitle or translation loading and the interface lagging, not measured CPU, memory or battery use. Vendors' own changelogs ("goodbye lag", "optimized extension performance") suggest lag is a real issue they hear about.

### Cited Findings
- **Trancy UI lag on YouTube (Mac):** a CWS review, surfaced via search snippet, says "When I access YouTube while using it on a Mac, the interface runs with a 1-second delay, which makes it feel laggy" and "There is an extra pause when opening videos and it feels very sluggish". The review was not shown on the fetched review page, so this is unverified — [CWS Trancy listing](https://chrome.google.com/webstore/detail/ai-subtitles-immersive-tr/detail/ai-subtitles-immersive-tr/mjdbhokoopacimoekfgkcoogikbfgngb). Trancy changelog entries mention "Reading mode subtitle performance optimization (goodbye lag)" and "Optimized extension performance" — [Trancy changelog p2](https://www.trancy.org/changelog?page=2)
- **Slow subtitle loading (LR):** a search snippet for thread 32244 says refreshing "usually takes a full 2 minutes for subtitles to load". Not verified verbatim in the fetch — [LR forum thread 32244](https://forum.languagelearningwithnetflix.com/t/lr-usually-gets-stuck-on-loading-subtitles-on-netflix/32244)
- **Slow translation (Immersive Translate):** "It's taking too long to translate. Much simpler way is to use google translate" — holysh, 2026-09-22 — [CWS Immersive Translate reviews](https://chromewebstore.google.com/detail/immersive-translate-trans/bpoadfkcbjbfhfodiogcnhhhpibjhbnh/reviews) (4.0★, 3.1K ratings). This may refer to web pages rather than video.
- **Netflix slow to load with the extension (Immersive Translate):** GitHub #1886 "[Bug]: Netflix taking forever to load" (closed 2025-01-16) — [Immersive Translate issues](https://github.com/immersive-translate/immersive-translate/issues?q=subtitle+netflix)

### Inferences
- Showing the user's own subtitle track immediately, before any machine translation is done, removes the "waiting for translation" delay. Saving translations as they arrive also helps.
- Keeping the extension light on the player page (no heavy work while the video plays) addresses the "sluggish" complaints.

### Gaps
- No user-reported CPU, memory or battery figures found for any dual-subtitle tool.
- No reports found of an extension slowing video decoding or causing dropped frames.

## Interference with the site's own captions or playback

### Takeaway
Only indirect evidence was found. Users complain about two sets of subtitles showing at once, and about the site's control bar fighting with the overlay for screen space. No reports were found of an extension changing the site's saved caption settings or clicking through to pause the player.

### Cited Findings
- Two sets of subtitles showing at once — [LR forum thread 5050](https://forum.languagelearningwithnetflix.com/t/post-your-rants-about-language-reactor-update-here/5050/20) (2021)
- "further hindered by Netflix UI popping up" — [LR forum thread 25297](https://forum.languagelearningwithnetflix.com/t/pin-on-video-subtitles-on-the-bottom-of-the-screen/25297) (2024)
- LR's workaround for its own dependency on the site's subtitles: users are told to check that Netflix subtitles are turned on in Netflix, which means the extension depends on the site's caption state — [LR search results summary for thread 41812](https://forum.languagelearningwithnetflix.com/t/language-reactor-stuck-on-loading-subtitles-on-netflix/41812)

### Inferences
- The extension should not permanently change the user's caption preference on the site, and it should restore the native captions when turned off.

### Gaps
- No direct reports found of extensions pausing playback unexpectedly, swallowing clicks on the player, or resetting caption settings. Searching the Chrome Web Store for terms like "pause" or "click" might turn some up.
